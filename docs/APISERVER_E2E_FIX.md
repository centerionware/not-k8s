# nodeapiserver e2e fix tracker

This is the living log for failures found while bringing `nodeapiserver` to
parity with the upstream kube-apiserver. Each independent defect gets its own
branch and PR into `nodeapiserver`; a PR is not marked fixed until its focused
e2e test passes. Failures that occur after the API listener is lost are marked
for triage rather than assumed to be separate defects.

Initial evidence: [full e2e run 33541038722](https://github.com/centerionware/not-k8s/actions/runs/33541038722), commit `6c6c0060`.

| nodeapiserver's internal watch-cache reflector spins without backoff on a canceled/ended watch | **fixed** | Traced live from full run `33713316765`: shard 4 ran ~40 tests fast and clean (1-8s each) right up until its clustered disruptive/restart-triggering tests began, then `nodecontroller`'s journal showed a sustained burst of `WatchFailed ... 410 Gone: the requested resource version is too old — relist required` across ~15-20 distinct resource kinds (ServiceAccount, ConfigMap, Role, ResourceClaim, ControllerRevision, EndpointSlice, ...) recurring every ~100-150ms, landing on `test_cert_manager_crds_are_usable_without_nodecontroller_restart` timing out waiting 30s for its namespace's default ServiceAccount — one of 7 tests in that cluster that all failed identically (~30-31s each). Root cause: `cacher::driver::reflect()`'s three "the watch needs a fresh LIST" arms were asymmetric — the `Err(e)` arm correctly waits `DEFAULT_RECONNECT_BACKOFF` (1s) via `wait_or_stop()` before relisting; the `canceled` (compacted/canceled watch) and `Ok(None)` (stream ended cleanly) arms both relisted **immediately**, no backoff. PR #522 gives the `canceled`/`Ok(None)` arms the same backoff the `Err(e)` arm already had.
