# nodemigrate bug and fix tracker

Last updated: 2026-09-25

This living list tracks defects exposed while exercising nodemigrate against
the latest regular release (`v0.8.0` at the time of the run), their owning
components, branch fixes, and focused evidence. Release-backed failures caused
by old component binaries remain visible until the fixes are included in the
coordinated `v0.8.1` release.

Latest branch-runtime integration [36168559234](https://github.com/centerionware/not-k8s/actions/runs/36168559234)
at code SHA `29b6b7de9575e7cf0d43ca60becba868373d86f3` passed nodemigrate and
combined-runtime builds and the five-node Docker isolation preflight. Exact
source Cilium process cleanup found no remaining source daemon and removed
three stale Envoy sockets. The previous AppArmor fix also remains verified:
CRI received `Unconfined` and Cilium `mount-cgroup` mounted cgroup v2 in run
`36165304330`. Both migration lanes passed their source fixtures, then failed
before a target workload checkpoint. K3s Cilium init containers and its agent
started, but nodelet/containerd continued reporting `cni plugin not
initialized`, so CoreDNS and hostPath CSI workloads could not recover. The
upstream target API rejected `CertificateRequest migration-test-1` with HTTP
500 after logging that the cert-manager admission webhook request failed;
this coincided with broken target CNI. Upstream rollback restored its source
API and both exports were retained. Neither lane reached reverse migration or
parity comparison. Exact job logs are saved at
`/tmp/nodemigrate-36168559234/{k3s,kubernetes}.log`.
